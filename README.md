# Ремонтная мастерская

Учебный веб-проект по практике: приложение сервисного центра для приёма заявок на ремонт техники, отслеживания статусов и учёта запчастей.

**Стек:** Python 3.11+, FastAPI, SQLAlchemy 2.0, SQLite, Jinja2, HTML/CSS/JS. Графики — Chart.js (лежит локально в `app/static/vendor`).

## Возможности

**Клиент**
- каталог услуг с ориентировочными ценами и сроками;
- регистрация и вход;
- создание заявки: тип устройства, модель, серийный номер, описание неисправности, фото до 5 МБ;
- личный кабинет: активные заявки, история, стоимость работ и запчастей;
- пошаговый индикатор статуса и журнал изменений;
- отмена заявки, пока она не принята мастером в работу.

**Мастер**
- список назначенных заявок и счётчики по статусам;
- карточка заявки с данными клиента и фото;
- смена статуса с комментарием (переходы ограничены жизненным циклом);
- добавление запчастей со склада (автоматическое списание остатка) и возврат на склад;
- указание стоимости работ, автоматический расчёт итога;
- публичные и внутренние комментарии.

**Администратор**
- обзорная панель: активные заявки, заявки без мастера, низкие остатки;
- список заявок с фильтрами по статусу, мастеру, клиенту и устройству;
- назначение и снятие мастера, смена статуса, комментарии;
- CRUD услуг (цена «от», срок, скрытие из каталога);
- склад: карточки запчастей, приход/списание, минимальный остаток;
- пользователи: создание сотрудников, роли, блокировка, сброс пароля;
- статистика: заявки по дням, выручка по месяцам, типы устройств, загрузка мастеров, разбивка по статусам.

## Быстрый старт (Windows)

```powershell
cd D:\File\file\Project\Pr_1
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Откройте <http://127.0.0.1:8000>.

При первом запуске база `workshop.db` создаётся автоматически и наполняется демо-данными. Чтобы запустить с пустой базой, установите переменную окружения `AUTO_SEED=0`.

## Роли и доступ

| Раздел | Клиент | Мастер | Администратор |
| --- | --- | --- | --- |
| Каталог, главная | ✓ | ✓ | ✓ |
| Свои заявки | ✓ | — | — |
| Назначенные заявки | — | ✓ | — |
| Все заявки, услуги, склад, пользователи, статистика | — | — | ✓ |

Проверка роли выполняется на сервере в зависимостях FastAPI (`require_roles`), а не только скрытием ссылок в интерфейсе. Клиент не получит чужую заявку по прямому URL: карточка дополнительно сверяет `client_id`.

## Работа со статусами

`Принята → В диагностике → В ремонте → Готова к выдаче → Выдана`

- мастер может двигать заявку только по разрешённым переходам (`MASTER_TRANSITIONS`);
- администратор может установить любой статус;
- клиент может только отменить заявку в статусе «Принята»;
- каждый переход пишется в `request_status_logs` с автором, временем и комментарием.

## Безопасность и валидация

- пароли — PBKDF2-HMAC-SHA256, 260 000 итераций, случайная соль; в БД хранится только хеш;
- сессия — подписанная HMAC-SHA256 cookie с сроком 7 дней, `HttpOnly`, `SameSite=Lax`;
- CSRF — double-submit cookie: токен из формы сверяется с cookie;
- SQL-инъекции — все запросы через SQLAlchemy ORM/параметризацию, конкатенации SQL нет;
- валидация на сервере: e-mail, телефон, длины полей, цена, количество, роль, статус;
- загрузка фото: белый список расширений, проверка сигнатуры файла, лимит 5 МБ, случайное имя;
- разграничение доступа к объектам (чужие заявки недоступны).

## Тестирование

```powershell
.\.venv\Scripts\python.exe -m pip install pytest httpx
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты используют отдельную временную БД (`DATABASE_URL`), проверяют регистрацию/вход, защиту разделов по ролям, создание заявки и смену статуса.

## Ограничения учебной версии

- SQLite и синхронный SQLAlchemy — для одного процесса; для нагрузки нужен PostgreSQL и миграции (Alembic);
- уведомления по e-mail, PDF-акты, QR-коды и Kanban не входят в обязательное ядро;
- CSRF-токен живёт в cookie до истечения сессии, отдельного обновления нет.
