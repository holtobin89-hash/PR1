# Сценарии проверки

Ручные сценарии для демонстрации на защите. Автоматическая часть — `pytest`.

## 1. Клиент

1. Открыть `/register`, создать аккаунт (пароль короче 8 символов → ошибка валидации).
2. Войти, открыть «Новая заявка».
3. Отправить пустую форму → ошибки «выберите тип», «опишите неисправность».
4. Заполнить: тип «Смартфон», модель, описание ≥ 10 символов, приложить фото > 5 МБ → ошибка про размер; приложить PNG → заявка создаётся.
5. В карточке проверить номер `RM-ГГГГ-XXXX`, статус «Принята», пошаговый индикатор, фото.
6. Нажать «Отменить заявку» → статус «Отменена», запись в истории.

## 2. Администратор

1. Войти `admin@workshop.ru` / `admin12345`.
2. `/admin/requests` — фильтры по статусу, мастеру и поиск по клиенту/устройству.
3. Открыть заявку → назначить мастера, сменить статус на «В диагностике».
4. `/admin/services/new` — создать услугу; проверить, что она появилась в `/catalog`; скрыть её (снять «активна») → пропадает из каталога, остаётся в старых заявках.
5. `/admin/parts` — приход `+5`, списание `-2`; попытка списать больше остатка → отказ.
6. `/admin/users/new` — создать мастера; заблокировать его → вход возвращает «Учётная запись заблокирована».
7. Попытаться заблокировать самого себя → ошибка.
8. `/admin/stats` — графики заявок, выручки, устройств и загрузки мастеров отображаются.

## 3. Мастер

1. Войти `master@workshop.ru` / `master12345`.
2. Убедиться, что видны только назначенные заявки; открыть чужую по прямому URL → 404.
3. Сменить статус «В диагностике» → «В ремонте», добавить комментарий.
4. Попробовать перескочить с «В ремонте» на «Выдана» → отказ.
5. Добавить запчасть со склада → остаток в `/admin/parts` уменьшился, сумма заявки пересчиталась.
6. Указать стоимость работ `2 500,50` → итог = работы + запчасти.
7. Убрать запчасть → остаток вернулся на склад.
8. Перевести заявку в «Готова к выдаче», затем «Выдана» → появляется в истории, в выручке статистики.

## 4. Безопасность

1. Без входа открыть `/admin` → редирект на `/login`.
2. Клиентом открыть `/admin` → редирект в `/client`.
3. Отправить POST с поддельным `csrf_token` → 400.
4. Клиент открывает чужую заявку `/client/requests/<id>` → 404.
5. В БД (`users.password_hash`) нет открытых паролей — только `pbkdf2_sha256$...`.

## 5. Адаптивность

Проверить в DevTools на ширине 375 px: бургер-меню, карточки в одну колонку, таблицы прокручиваются, формы не выходят за экран.
